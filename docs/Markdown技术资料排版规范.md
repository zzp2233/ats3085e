# Markdown 技术资料排版规范

适用于本仓库面向读者的学习笔记、源码导读、调用流程、调试复盘和操作说明。默认在 Typora 中阅读。读者了解 STM32 基础开发，正在学习 ATS3085E、UMA503 和联网。

照着文档阅读时，应能先找到自己要看的模块，再顺着一行一个动作的说明定位代码。文档的详细程度可以随任务变化，关键条件、失败分支和参考位置要说清楚。

## 一、先组织阅读顺序

1. 全文使用一个一级标题。按实际工作流程用二级标题划分阶段，有多个设备、角色或模块时再用三级标题分开。
2. 开头用一小段交代涉及哪条路径、从哪里开始、讲到哪里为止。涉及多端或多任务时，可以先放总图，再按图中的阶段展开。
3. 有先后顺序的操作用编号列表。并列条件、注意事项或备选路径用无序列表。对照寄存器字段、状态码或两端行为时用表格，过程说明放回步骤列表。
4. 讲现有项目时，优先沿实际入口展开。存在多条路径时，先给出本节采用的入口，再在分支发生处说明条件。

## 二、每个步骤按一眼能扫完的方式排版

1. **首行写简短、加粗的动作。** 例如「打开本次 DMA 会话」。读者只扫这些首行，也能看出整体顺序。
2. **从下一行开始说明。** 每行讲一个主要动作、条件或结果。比如先写调用了哪个函数，下一行写它配置了什么，再下一行写满足什么条件才继续。连续紧密相关的细节可以留在同一行。
3. **用 Markdown 硬换行保留这几行。** 在需要强制换行的源码行末加两个半角空格。后续行与列表项正文对齐，单数字编号 `1. ` 后的续行缩进三个空格。通过预览确认续行仍属于同一个编号。 [CommonMark 硬换行](https://spec.commonmark.org/0.31.2/#hard-line-breaks) · [CommonMark 列表项](https://spec.commonmark.org/0.31.2/#list-items)
4. **同一步内紧凑排列，独立步骤之间留空行。** 一步内容长到包含多个独立操作时，拆成两个步骤。短结论可以单独占一行并加粗，方便回看。
5. **源码链接跟在对应说明末尾。** 一两个短链接可以跟在步骤的最后一句末尾。链接较多时另起一行。长路径放在链接目标中，链接文字写成「SPI 配置」「DMA 开始搬运」等能辨认内容的短句。

## 三、用代码和图帮助跟读

- 函数名、变量名、寄存器、宏、命令和字面值用行内代码。简短调用链可以写成 `入口函数()` → `中间函数()` → `处理函数()`。调用链太长时，按执行阶段拆行。
- 一步中如果涉及新概念，先讲正在发生的事，再说明这个概念怎样影响下一步。例如「RX DMA 写完当前槽」「SPI 任务失效缓存」「CPU 读取这帧」。需要说明复用时，写出谁写、谁读、什么时候可以覆盖。
- 关键判断尽量给出实际观测项，例如哪个状态位、哪个返回值、哪条日志，或哪一个 ACK 字段能证明完成。源码定位用实际函数名和核实过的文件行号。涉及条件编译、多个 SDK 副本或历史版本时，注明当前使用的分支或路径。
- 流程图适合画分支和回路。时序图适合画两端收发、任务通知以及缓冲区交接。图上的函数名和步骤列表保持一致，重要判断也写在正文，方便逐步读源码。
- 图用 Typora 支持的 Mermaid 语法。针对本项目用户遇到的 Mermaid 8.14.0，优先使用简单的 `graph TD`、`graph LR` 和 `sequenceDiagram`。连线标签尽量短，多个信号名之间可用空格，例如 `CS SCK MOSI`。修改后在目标版本检查图能否渲染。 [Typora 绘图说明](https://support.typora.io/Draw-Diagrams-With-Markdown/#mermaid)

## 四、照这个例子写

下面是 Markdown 源码。每个步骤的标题和中间说明行末都有两个半角空格，Typora 会把它们显示为同一个编号下的独立行。

```markdown
## 1. 两边怎样把 SPI 配好

### 3085E 主机

1. **配置本次 SPI 会话。**  
   `sfile_run_context()` 构造本次使用的 `spi_config`。  
   配置选择主机、SPI Mode 3 和 8 位字宽。  
   运行时使用入口传入的 `hz` 作为请求频率。

2. **启动 RX DMA。**  
   `spi_acts_spi2_circular_open()` 配置一个 1024 字节的接收区。  
   驱动开启硬件重载，再启动 RX 通道。  
   后续每笔 SPI 事务在接收区的前半或后半交付 512 字节。
```

## 五、交付前检查

- 先扫标题和每步的加粗首行，确认能看出执行顺序。
- 看预览，确认步骤内有硬换行，步骤间留白，编号和缩进正确。编辑器清理行尾空格时要保留用于硬换行的空格。
- 点击源码链接，核对文件和行号，并确认各图在目标渲染环境中正常显示。
- 若任务只要求重新排版，保留原有技术结论、调用顺序、链接和图。发现内容疑点时，在交付说明里指出。
