## 一、本次提交做什么（一句话）

把 ATS3085E（主机）与 UMA503（从机）之间的 SPI 双向链路从「PIO + 812.5 kHz + 256 字节帧」逐步提速到「硬件 PDMA + 4 MHz + 512 字节双帧块（V10）/ 硬件 RX 环形 reload（V11）」，并新增单线 READY 握手（V7～V9）、4 MHz 文件传输协议（SPI FILE V1），两端配套、协议字节级一致。

## 二、定位与判据

- 现象：256 字节 v3 帧在 812.5 kHz 下单帧约 2.56 ms 起步，提时钟无效（瓶颈在每帧固定开销与从机 CPU 抢占），坏帧时从机 FIFO 穿底。
- 拆解：1) 时钟分频精度不足且 `clk_set_rate` 不返回错误（ATS 侧）→ 2) 主机驱动时间闸门过早返回、两帧时钟叠加 → 3) 从机 PIO 供数能力不足（503 侧 CPU 抢占）。
- 判据：主机 shell 命令返回 PASS、`confirmed=count、retries=0`；从机侧 `ok=count、bad=0`；READY 等待统计无超时。
- 根因结论：提速不靠单提时钟，靠「加大帧长摊薄固定开销（V10）+ 硬件 DMA/环形 reload 摆脱 CPU 供数（V5/V11）+ READY 握手消除固定间隔余量（V7～V9）」三件事。

## 五、验证结果与边界

- 验证命令（主机侧）：`spi2swapdma 10000 10 4000000`（V5）、`spi2swapready 10000 0 4000000`（V7/V9）、`spi2swapblock2 5000 0 4000000`（V10）、`spi2circ 10000 0 4000000`（V11）；判据为 PASS、`confirmed=count、retries=0`，从机侧 `ok=count、bad=0`。
- 自动化回归：两仓库 `tests/` 下脚本分别覆盖对应版本，`run_spi_v11a_checks.py` / `run_spi_v11_checks.py` 可一键跑完。
- 边界（未证明/不能外推）：
  - V10/V11 必须**两端配套**固件，与 V9A 混用不被支持（block2 有显式拒绝）；
  - READY 链路故障后令牌状态跨命令存活，恢复手段是**双板重启**，不是重跑命令；
  - 4 MHz 已实测，8 MHz 上限仅由参数范围预留，未作为交付结论；
  - 从机诊断时钟为 OSA tick（5 ms）粒度，只能定位 tick 级停顿，亚 tick 延迟需逻辑分析仪（GPIO53/GPIO61 波形）。
- 提交前注意：两仓库 `tests/__pycache__/` 建议加入 `.gitignore`，不要提交。
