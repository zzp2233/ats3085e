UMA503 软件分层：你的代码在第 1 层，厂商的东西在第 2~5 层
ASR1605 OpenCPU · 从应用一路看到寄存器 · 数值与路径取自 2026-11-26 实机构建
应用层
app / APP LAYER
1
app_main_entry()
唯一应用入口。装载完成后由厂商库回调，里面只做“启动任务”，不做初始化大循环。
demo/ 业务模块
SPI 从机双槽、文件组协议、HTTPS 交付、OneNET 会话。你改的东西全在这层。
构建三件套
build_app.bat 入口、app_cflag.txt 变体清单、XIP 链接脚本。
用户 API 层
umapi / SDK HEADERS
2
um_nw / um_http / um_mqtt
网络类：注网、DNS、TLS、HTTP、MQTT。503 最值钱的能力都从这几个头文件进来。
um_spi / um_gpio / um_fs
外设类：SSP 配置、引脚、文件系统。Mode 3、位宽、频率都在 um_spi_init 里定。
只有 inc，没有 src
实现全在 common/lib/um_app.lib（349 KB）。点进函数看不到代码是正常现象。
厂商库与协议
LIB + PROTOCOL
3
um_app.lib
预编译二进制。链接时 --whole-archive 拉进来，你的入口不会被裁掉。
pcac：lwIP + mbedTLS
IPv4 套接字、DNS、证书校验、握手与加解密，HTTPS 全走这里。
3g_ps：蜂窝协议栈
SIM、附着、承载、PS 域状态机。CEREG 这类状态就是它报出来的。
操作系统层
os / OSA + NUCLEUS
4
OSA 统一封装
OSATaskCreate / OSASemaphoreCreate / OSATaskSleep。你只该用这一层。
Nucleus 内核
os/nu_xscale（OSA_NU_XSCALE）。优先级 0~255，数字越小越优先。
一个 tick = 5 ms
SECOND 200u 就是这么来的。任何“睡 1 个 tick”都是 5 ms 起跳。
硬件抽象层
hop / hal / csw
5
SSP = 你口中的 SPI
ARM PL022 同步串口，SSP2 就是那组四根线，与其他端口分开编址。
GPIO / PMU / DMA / INTC
READY 令牌、唤醒探针、描述符搬运、中断分发都在这一层。
寄存器级，只读不写
可以读头文件理解位定义，但不能直接改厂商的私有寄存器。

约束 1 · 32 KB 数据窗口
app.map 实测已用 29,024 B（88.6%）。48 KB 组缓冲只能 malloc。
约束 2 · 代码在 Flash 里 XIP
热路径代码塞进 .data 拷到 RAM 执行，避开 XIP 取指等待。
约束 3 · 新增 .c 要进 Makefile
demo/Makefile 不列就编不进去，症状是 app.map 搜不到、功能静默缺失。
读码顺序：app_main_entry → spi_link_test_start → spi_link_test_task → spi_link_dma_circular.h → spi_link_file_slave.h → spi_link_https.c
