UMA503 启动链与任务：从 BootROM 到两个常驻任务
app_main_entry() 只做两件事：拉起 SPI 任务、拉起 OneNET 任务 · 所有初始化都发生在任务里
① BootROM
片内固化代码。只认 Flash 起始处，按芯片自身流程往下跳。
② boot33
读 loadtable 分区表，决定每个镜像搬到哪、以 XIP 还是 PSRAM 运行。
③ 装 CP / DSP / RF
模组自己的协议栈、音频与射频镜像，先于你的应用就位。
④ 装 app.bin
你的镜像落到 0x8037A000，512 KB 窗口内，由 um_app_header 描述入口。
⑤ app_main_entry
厂商库在可用线程上下文里回调。这里只创建任务，不做大循环。
⑥ OSA 调度
Nucleus 接管 CPU，tick = 5 ms。
任务 A · spi_link（优先级 80，4 KB 静态栈）
独占 SSP2，做从机双槽 DMA 收发。
每块 512 B 帧 / 480 B 正文，READY 决定主机可发几块。
组齐后把缓冲交给交付 worker，交给 HTTPS 或落盘。
任务 B · onenet_boot（优先级 90，10 KB 堆栈）
等网络注册（CEREG）与有效 UTC，再建 MQTT 会话。
上报 record_state，处理 bind_status 类下行属性。
断线重连与应答超时都由这个任务自己管。
503 和模组打交道的三条通道（这是 OpenCPU 最特殊的地方）
① 你的代码调 SDK：um_http / um_mqtt / um_nw / um_spi，链接期定地址，就是普通 C 调用。
② 模组反向调你：cust_src/um_api_map 的 v_user_api_table 放进 DDR_USER_API_TABLE 段，字段是 {函数名哈希, 函数指针}，运行期按哈希查表。
③ AT 命令直接进你的函数：cust_src/um_atsever/um_atsrv.c 用 utlAtParameter_T 注册参数、ATRESP() 回包，这是 503 排障的主入口。
ATS3085E · 有手有脚的业务端
Zephyr 内核，编译期注册表决定初始化顺序。
录音、屏幕、UI、本地文件、源数据可回读。
对外只看到一组 SPI 帧和 READY 信号。
UMA503 · 有嘴有耳朵的通信端
Nucleus + OSA，app_main_entry 手工起任务。
注网、TLS、HTTP、MQTT、断网重连、下行属性。
不碰录音和 UI，只把字节交给云端。
