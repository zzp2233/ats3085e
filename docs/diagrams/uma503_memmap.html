起点不是 0x80000000。
variable_def.mk 写死 APP_CODE_XIP_FLASH_ORIGIN=0x008037A000。这 512 KB 是 2 MB Flash 里划给你的窗口。
热点代码靠 .data 搬到 RAM。
链接脚本把 .spi_crc.text、.spi_dma.text 归进 .data，启动时从 Flash 拷到 RAM 执行。XIP 取指要等 Flash，SPI 热路径在 RAM 里跑才不卡顿。
链接期就会报错。
ASSERT(__flash_end <= ORIGIN(flash)+LENGTH(flash)) 把超限拦在链接阶段，代码超 512 KB 直接失败。

.data + .bss = 29,024 B / 32,768 B。往 .bss 加静态数组要按字节算账。
所以大缓冲只能 malloc。
spi_link_file_slave.h 的 group_buffer = malloc(min(文件字节, 100×480))，约 48 KB，会话结束时 free。
堆不在这 32 KB 里。
LDFLAGS 有 --wrap=_malloc_r，malloc 走 SDK 堆实现，所以 10 KB 任务栈能分配成功。
检查手段：app.map 里搜 __ram_end、__flash_end 与 .bss；.ld 里两个 ASSERT 负责在链接期拦住越界。
