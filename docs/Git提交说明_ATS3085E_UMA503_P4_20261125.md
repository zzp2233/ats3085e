# ATS3085E 与 UMA503-V7 P4 Git 提交说明

北京时间 2026-11-25。比较 ATS `0684a28` 和 UMA `120c024` 到当前工作区。上轮 P3 使用 PC 发起业务会话。本轮在板端使用 265,113 B 的可回读内置 M4A，完成 init、PUT、对账与 complete。复盘另载 [故障、接线、源码阅读和上板判据](ATS3085E与UMA503_P4板端录音上传调试复盘_20261123-25.md)。

## 1. 问题及验收

| 现场证据 | 本轮要求 |
|---|---|
| init/PUT/complete 响应丢失或收到 403/503 | 分清是否已向后端发送，按同 ID 查询远端实际进度，有界恢复 |
| 128 KiB 请求提示与服务端返回 265,113 B 的一片不同 | 按后端范围读文件，完整校验长度、响应和确认状态 |
| ATS 2 KiB Shell 栈溢出；UMA CP 网络任务分配 4 KiB 却登记 1 KiB | 各跟实际任务及 ELF/镜像，分别记源码修复与历史固件修订 |
| MISO 持续偏移、启动无 SCK、QUIET 入口 CSS 回落 | 用严格 CRC、witness、cookie、DMA 边界及首错确定恢复层次，当前调用结果保持正确 |
| 网络中断长于原重试预算 | 在整体期限内等待重新注册，不把硬件 STOP 当作网络失败重试 |

## 3. 构建、验收及回退

本次文档整理重新计算了 WITNESS 主机包和 STAGE3_CSS 从机包的 SHA-256，并复跑 PC 参考状态机（9 项通过）。表中 ARM 模型、编译与实机结论来自对应历史诊断包。

| 层级 | 本轮记录 |
|---|---|
| 模型 | P4 归档 `bootrecover_delivery_checks.json` 对应历史 BOOTRECOVER 的 191 项离线检查。WITNESS 的 `witness_endpoints.log` 有 4 项通过，包含注入后下一任务可用、错误 ACK 与关闭开关 |
| 固件 | 按 `delivery_manifest_witness.json`、`delivery_manifest_bootretry.json` 核对 pair。CP 栈修订、fixture 和签名配置按原交付保管 |
| 实机 | `app spi2soak 1 10000 5000` 用于离线空闲及 QUIET。 `app p4upload <14位测试ID> 4096` 用于新 ID 与同 ID。WITNESS 专用包对已完成 ID 加 `witness-once`，当前 FAIL，随后普通命令只查 init 并 PASS |
| 对比 | 13:50 新 ID 四次 HTTP 200，265,113 B。14:37 捕获恢复 8 帧，14:38 34 帧同 ID 查询通过。15:03 单独验证启动次序 |
| 未验和归因 | 本轮服务器 265,113 B 独立对象回下载待验，真实多片、掉电持久化和首个物理失步原因仍需取证 |

推荐成对提交协议和恢复变更，后补文档。需拆分时，将 P4 状态机加入 ATS 的同一可构建提交，诊断及构建选项可按依赖另分，记录配套 UMA 提交号。回退到 P3 使用 ATS `0684a28` + UMA `120c024` 的配套固件，两个板子共同复位，按 P3 的 PC 辅助流程复测。远端记录先同 ID 查状态再判断是否续传。暂存前检查两个仓库的现有差异与未跟踪文件，仅暂存预期源码、测试及 Markdown，不纳入录音 fixture、私有配置、签名地址、烧录包或原始日志。

## 4. 七段 Git 提交正文

### ATS3085E

~~~text
feat(p4): 在 ATS 板端完成录音上传对账与 SPI 恢复

一、问题定位
- P3 依赖 PC 编排；P4 遇到本地分片假设、2 KiB Shell 栈耗尽、READY 启动及事务错位问题。

二、分文件改动
- p4_upload.c/.h、p4_json.c/.h 新增板端业务状态、实际范围校验、响应解析与同 ID 恢复。
- spi_link_p4.h 适配 SPI、设备、录音与随机数入口。
- p4_fault.h 和 spi_link_soak.h 提供受控故障与有界诊断。
- spi_link_file_host.h、spi_link_file_protocol.h、spi_link_ready.h 增加扩展请求、启动与运行中同步。
- CMakeLists.txt 与 system_app_shell.c 按构建选项接入；扩充主机 ARM 模型。
- 配套 UMA 基线 120c024 之后的本批协议与恢复修改。

三、验证命令
- 在配套 P4 固件运行 app p4upload <测试ID> 4096。
- 诊断组合运行 app spi2soak 1 10000 5000。
- WITNESS 组合对已完成 ID 加 witness-once，再原 ID 普通复跑。

四、验证结果
- 13:50 新 ID 265113 B，四次 HTTP 200，最终 SYNC_SUCCESS。
- 14:37 注入恢复 8 帧；14:38 不重启按同 ID 只查一次 init。
- 15:03 ATS 先启动时允许第一次零事务失败，第二次成功。

五、未证明与已知限制
- 服务器对象独立下载、长录音真实多片及自动落盘待验。问题首次物理触发仍未定位。

六、遗留与回滚
- 保留诊断标记，回退配对 ATS 0684a28 / UMA 120c024。远端进度先同 ID 对账。

七、硬件与环境
- 两端固件配对，4 MHz Mode 3，双串口取证。私有配置和录音只用于本地验证构建。
~~~

### UMA503-V7

~~~text
feat(spi): 支持 P4 设备查询与有界 DMA 重同步

一、问题定位
- 启动后 READY 可能与原会话不同，运行中见 MISO 持续错位。
- QUIET 停止后 CSS 回落曾触发 -231，完整帧已通过校验。

二、分文件改动
- spi_link_device_info.c 返回设备及 UTC，spi_link_radio_test.c/.h 提供构建门控的断网诊断。
- spi_link_file_protocol.h、spi_link_file_slave.h 适配设备查询、网络及恢复状态。
- spi_link_dma_circular.h 增加启动信标与重同步、首错和 QUIET 停止重装检查。
- spi_link_https.c/.h 扩展连接错误、网络和射频诊断。
- makefile.mk、demo/Makefile、onenet_bootstrap.c 隔离外部构建和私有输入；扩充从机模型。
- 配套 ATS 基线 0684a28 之后的本批协议与恢复修改。

三、验证命令
- 配成对固件运行 app spi2soak 1 10000 5000 及 app p4upload <测试ID> 4096。
- 通过 WITNESS 诊断组合对已完成 ID 注入一次，采集异常双槽、恢复与普通重试。

四、验证结果
- CSS 版五秒 QUIET 重装通过，新 ID 265113 B 完整闭环。
- 注入波形 8 帧双向 CRC 正确，末两帧 RESYNC ACK 匹配；主机同 ID 重试仅 init。
- 真实中途断网恢复为单独用例，完整失败记录保留。

五、未证明与已知限制
- guard、CRC 和恢复通过不覆盖所有上电毛刺、硬件 cache 与电气条件。
- 历史 CP 网络栈登记修订属于特定镜像，换版本仍需复验。

六、遗留与回滚
- 保留首错、恢复次数和 QUIET 日志。回退配对 UMA 120c024 / ATS 0684a28。

七、硬件与环境
- COM6 从开机连续记录。控制 RESET、READY 和探头接线。私有配置、证据和包留在仓库外。
~~~
